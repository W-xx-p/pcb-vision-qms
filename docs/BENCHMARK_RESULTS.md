# VisA PCB 真实基准结果

> 执行日期：2026-10-08。以下数据来自公开 VisA PCB1～PCB4 的实际运行，不是估算值或演示占位值。

## 结论

在统一 64-shot、CPU-only 协议下，PatchCore 的四类别宏平均图像 AUROC 最高（0.849253），PaDiM 以更低 P95 延迟取得接近的像素 AUROC 与更高宏平均 F1。参考图基线速度最快，但识别能力有限。仅训练 8 批的 EfficientAD 波动明显，不应作为默认生产模型。

| 后端 | 图像 AUROC | 像素 AUROC | F1 | Recall | P95 延迟 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Reference | 0.611158 | 0.790342 | 0.666625 | 0.848958 | 100.382 ms |
| PatchCore | **0.849253** | **0.973989** | 0.753442 | 0.784375 | 611.481 ms |
| PaDiM | 0.815853 | 0.973067 | **0.763125** | 0.870833 | 170.120 ms |
| EfficientAD（8 batches） | 0.550286 | 0.740290 | 0.685633 | **0.939583** | 1219.380 ms |

宏平均为 PCB1～PCB4 各类别三随机种子均值的等权平均。高 Recall 不能单独代表模型优秀；例如 EfficientAD 在部分类别通过几乎全部判异常获得高 Recall，但 F1、AUROC 与误报控制较差。

## 实验协议

- 数据：Amazon VisA 20220922，PCB1～PCB4，共 4,416 张；数据清单 SHA-256：`50c3bf20da3279b17f17911f86026c89604abe39f77430e1fe6bb9d664aeadfb`。
- 划分：官方 1-class split；每类别训练集随机选择 64 张正常图，校准集占测试正常/异常样本各 20%，指标在剩余完整测试样本上计算。
- 重复：随机种子 17、42、73；表中为总体均值与总体标准差。
- 输入：256×256；像素 AUROC 在统一 256×256 异常图上计算。
- PatchCore：1% coreset；PaDiM：默认 Anomalib 2.2 配置。
- EfficientAD：本地正常训练集作为辅助数据，8 个训练批次；为适配 3.736 GiB Docker 内存而显式限制。
- 推理：导出 OpenVINO IR 后逐张 CPU 推理；延迟包含图片数组进入后端到返回分数和异常图，不包含 HTTP、数据库或对象存储。
- 环境：Windows + Docker Desktop，Docker 可用 8 CPU / 3.736 GiB RAM，PyTorch 2.8.0+cpu、Anomalib 2.2.0、OpenVINO 2026.4.1。

## 重要边界

- VisA 官方划分的数据质量扫描发现 338 组跨训练/测试近重复候选，精确重复组为 0，因此数据质量门禁为未通过。结果可用于工程对比与公开复现，但不应被包装成严格无泄漏的学术 SOTA 结论。
- 这是公开数据、低内存 CPU 主机上的少样本基准，不代表目标工厂相机、光照、节拍和缺陷分布。量产前仍需使用目标产线数据做 Golden Set、GR&R、误报/漏报成本和节拍验收。
- EfficientAD 仅运行 8 个训练批次，其较差结果说明该资源受限配置不适合直接发布，不代表充分训练后的算法上限。
- 导出过程存在 Anomalib/PyTorch ONNX TracerWarning；当前 OpenVINO 推理和指标计算成功，依赖升级时仍需回归测试。
